Estado actual de la aplicación, capacidades disponibles y trabajo necesario para preparar una futura operación real.

Tecnología: Django 5.2 y PostgreSQL

Alcance confirmado: demostración académica con información sintética

Conclusión: la aplicación tiene una base funcional amplia para demostrar procesos de cementerio, pero no está certificada ni preparada para operar con datos reales, cobrar dinero real o emitir documentos tributarios.

Resumen ejecutivo

CementerioERP organiza el inventario de sepulturas y muestra flujos de personas, responsables, contratos, reservas, pagos, movimientos y gastos. Incluye perfiles de acceso, registro público de cuentas familiares, confirmación por correo, auditoría y documentos privados.

La demostración conserva PostgreSQL y utiliza datos ficticios, una parcela ilustrativa y un buzón académico local. Se pueden cargar planos y coordenadas propios, pero el proyecto no incluye el plano de un cementerio real. El uso real exige definir las reglas locales, adaptar integraciones y validar la operación con el personal.

Mapa y datos de demostración

El lote de ejemplo contiene 432 sepulturas en bloques C–H, con nombres colombianos verosímiles y códigos/números marcados como demostrativos. Es un escenario inventado: no representa ubicaciones ni identidades reales. El mapa puede sustituirse por un plano autorizado y ubicar las sepulturas mediante el flujo de administración.

La importación CSV permite agregar hasta 5.000 espacios por archivo, con vista previa y validación de códigos y ubicaciones. No elimina ni modifica espacios existentes. La calidad del mapa real dependerá de que el plano y las coordenadas se preparen y verifiquen en terreno.

Documentos, correo y finanzas: límites

  • Los contratos son plantillas imprimibles con condiciones editables y espacio para firmas manuscritas. El archivo firmado puede adjuntarse y versionarse; no es firma electrónica ni acredita autenticidad.
  • Facturas y recibos son documentos internos de la demostración. No son comprobantes tributarios autorizados.
  • Pagos, devoluciones y gastos se registran en el sistema; no se mueve dinero ni se conecta una pasarela o banco.
  • El correo académico se almacena en un buzón local. Para correo real se necesita SMTP, credenciales protegidas, dominio y pruebas de entrega.
  • Impuestos, mensualidades y procedimientos son configurables dentro del alcance existente, pero deben contrastarse con la normativa y políticas del cementerio elegido.

Qué falta para que sea un sistema real

  1. Definir el contexto: cementerio, municipio y país; responsables del sistema; usuarios y procesos vigentes.
  2. Aprobar reglas: tipos de sepultura, capacidad, contratos, tarifas, reservas, vencimientos, devoluciones, exhumaciones, traslados, archivos y retención documental.
  3. Preparar datos verificados: plano autorizado, inventario completo, personas y contratos migrados con responsables; revisión de duplicados y conciliación.
  4. Validar finanzas y documentos: asesoría contable/legal local, facturación electrónica cuando aplique, firma aceptada, impuestos y conciliación bancaria.
  5. Revisar privacidad y seguridad: base legal y avisos, retención/borrado, acceso mínimo, cifrado, gestión de secretos, revisión de vulnerabilidades y respuesta a incidentes.
  6. Desplegar y operar: hosting con HTTPS, base administrada y respaldos probados, monitoreo, correo transaccional, actualizaciones, soporte y recuperación ante desastres.
  7. Probar en paralelo: capacitación, pruebas con personal, conciliación contra registros oficiales, aceptación formal y plan de reversa antes de migrar a producción.
Recomendación: tratar el siguiente paso como una etapa de descubrimiento y piloto controlado. No cargar datos personales reales ni emitir cobros/documentos oficiales hasta cerrar y aprobar estos puntos.

Cómo iniciar la demostración

Con PostgreSQL disponible y el archivo local de configuración preparado, desde la carpeta del proyecto:

make demo

La aplicación se abre en http://127.0.0.1:8000. El comando prepara datos sintéticos y solicita una contraseña nueva para las cuentas de demostración. Para guía de exposición, consultar docs/entrega-academica.md; para operación y configuración, docs/operacion.md.
